## 口径与红线说明

- **98 分怎么来**：`0.30×层级 + 0.20×叙述 + 0.25×遗忘 + 0.15×min(1, 强化比/2.1) + 0.10×召回`（`benchmarks/run.py:172-178`）。实测 30+20+25+14.90+8.57=98.47，四舍五入为 98；表里的 2.1× 是 2.086 的显示值。红线 95 给综合分留 3 分缓冲，但任一子项掉线仍算回归。
- **两个召回口径不要混算**：`latest.md` 的 86% 是查询级（7 个带期望的查询命中 6 个）；文末逐查询表的 `2/2`、`1/1` 是关键词级（9/10），两者分母不同。`scale.md` 与 `e2e.md` 的召回都是查询级。
- **检索耗时只含** `seeds → activate → select → assemble`，不含建库、不含离线索引。跨机器不可比：同一份代码在本机复跑，SeekMemory 是 5.71ms，快照是 3.89ms；因此红线取 <20ms，而不是卡 3.89ms。
- **e2e 是抽样**：单次采样、主调用 temperature=0.7、LLM 判分有主观性。人味红线 4.30（低 0.14）是“允许噪声、拦住真回退”的折中；命中 9/9 是硬线。
- **对照方案不设红线**：滑窗/关键词/伪向量/摘要/全量是评测口径的一部分，不是优化目标；但改动了它们的实现必须重跑并注明，不能只报 SeekMemory 的数字。
- **注入字数**均为平均每查询字符数；`scale.py` 取整（`chars // 查询数`）。

## 怎么跑

在 `SeekMemory/` 下执行，三条命令分别重写对应的 results 文件：

```bash
python3 benchmarks/run.py          # → benchmarks/results/latest.md
python3 benchmarks/scale.py        # → benchmarks/results/scale.md
DEEPSEEK_API_KEY=sk-... python3 benchmarks/e2e.py   # → benchmarks/results/e2e.md
```

环境变量：

| 变量 | 作用 | 默认值 | 说明 |
|---|---|---|---|
| `SCALE_USERS` | `scale.py` 仿真用户数 | 8 | 只影响 owner/shadow 分布，不改变消息总数 |
| `SCALE_DAYS` | `scale.py` 仿真天数 | 60 | 与 `SCALE_MSGS` 共同决定总量 |
| `SCALE_MSGS` | `scale.py` 每天消息数 | 40 | 总量 = `DAYS × MSGS` |
| `DEEPSEEK_API_KEY` | `e2e.py` 调用模型 | 脚本内置 fallback，勿依赖 | 须显式设置；需外网，模型固定 `deepseek-flash` |

复现本文的 `scale.md` 快照：

```bash
SCALE_USERS=20 SCALE_DAYS=120 SCALE_MSGS=100 python3 benchmarks/scale.py
```

- `run.py` 纯离线、无外部依赖，固定数据集，确定性指标应逐位一致（实测复跑 `latest.md` 除单条耗时 0.5→0.6ms 外完全相同）。
- `scale.py` 纯离线；确定性指标（594/11406、5628/177/67/39/285/40 字、6/6…）复跑一致，只有毫秒数与本机负载有关（本机 5.71ms vs 快照 3.89ms）。
- `e2e.py` 会发 6 策略 × 9 题 = 54 次主回答 + 54 次判分请求，需要 key 和外网；结果依赖采样，跑完先看 `results/e2e.md` 的“失败 N 次”告警，有失败时不能直接拿数字对比。
- 三个脚本都会覆盖 results 文件；跑前先 `git status` / `git diff -- benchmarks/results/`，把数字变化和代码改动分开看。
