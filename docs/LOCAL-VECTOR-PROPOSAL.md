# 本地向量检索提案

状态：待审设计，尚未实现；不是 ISSUE-0024 的运行依赖或通过条件。
问题来源：ISSUE-0001 的零字面重合召回，例如“我是干什么的”与“量化交易项目开发”。

## 不可改变的约束

- 模型由用户在部署前自行预装并提供本地路径；运行时只读取该路径。
- 不发送查询、记忆、向量或用户标识到外部服务，不调用远程 embedding API。
- 不自动下载模型或运行时组件，不进行联网探测、遥测、远程代码加载或按次计费。
- 本次不选定模型、不加入推理依赖、不创建向量字段或索引，不修改 Artifact/Source 模型。
- 提案即使被否决，默认关闭但可独立启用的 BM25、现有图召回、评分与披露仍完整工作。

本地推理仍占用磁盘、CPU、内存并产生延迟。未来选型必须实测这些资源，不能将“无服务账单”
解释为“无资源开销”。模型许可证与分发条件也须随选型记录。

## 可复用的接口

继续通过现有 `app.ports.Retriever.retrieve(query, pool)` 接入召回，保留调用方传入的可见池。
本次已经允许注入检索器并提供缓存失效信号，无需为了预留接口新增空实现或空配置。

未来语义相似度不能填写 `RetrievalCandidate.lexical`：该字段已被现有评分层视作词面证据。
若立项，须在独立 Issue 中先确定语义候选如何携带分数、校准并融合，再经 Lead 审核契约；
此文档不提前把候选新字段或融合公式变成生效接口。

## 后续实现需回答的问题

| 事项 | 必须给出的证据或决策 |
|---|---|
| 模型与编码 | 本地文件、许可证、中文效果、维度、最大长度、池化及归一化方式 |
| 资源预算 | CPU 环境启动时间、常驻/峰值内存、索引大小、查询与增量编码延迟 |
| 索引标识 | 模型内容哈希、分词与编码设置、向量格式版本，避免不同模型的向量混用 |
| 索引失效 | Artifact ID/revision 与缓存版本；修改、遗忘、恢复、合并及模型更换后的重建策略 |
| 融合与闸门 | 语义信号独立校准，验证其增加召回时不会推高错误事实或压掉原图候选 |
| 隐私 | 仅在可见池中选候选和计算查询统计，候选继续经过同一披露与组装流程 |
| 失败与回滚 | 本地模型缺失、损坏或资源不足时显式禁用该能力，继续使用 BM25/图召回 |

索引及其模型标识属于可重建派生数据，不是 Source 真相。需要持久化时另行评审存储格式或迁移，
不在这次 BM25 PR 中建立隐含数据库约定。

## 独立验收与启用

后续 Issue 应先冻结跨表述、实体混淆、否定/时序、无答案与跨会话边界集，再比较图召回、
BM25 和混合向量三种路径。语义命中提高必须伴随噪声、资源与隐私指标报告；合成样本不能代替
staging 验证。CI 不下载模型，可用固定测试编码器验证接口，但真实效果仍须另有本地模型实测。

只有模型、契约、资源上限、融合规则与验收都经 Lead 批准后才开始实现，默认关闭并保留独立开关。
