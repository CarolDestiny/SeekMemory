# ISSUE-0017 没有相关性闸门：select 永远凑满 top-k，注入的 81% 是噪声

| 项 | 值 |
|---|---|
| 编号 | ISSUE-0017 |
| 级别 | P1（功能失效：精度系统性偏低） |
| 状态 | open |
| 发现方式 | `benchmarks/ablation.py` 消融实验 |
| 日期 | 2026-10-21 |
| 关联 PR | 待开（建议分支 `fix/issue-0017-recall-gate`） |

## 症状

消融报告里，**所有配置的噪声占比都在 81%~87%**：

| 配置 | 命中 | 注入字数 | 噪声占比 |
|---|---:|---:|---:|
| `full` | 18/18 | 104 | **81%** |
| `no_dedupe` | 18/18 | 127 | 83% |
| `no_weight_prior` | 16/18 | 126 | **87%** |

也就是说：每注入 5 个字，有 4 个与当前问题无关。命中率漂亮，是因为黄金集只有 20 条，而 top-8 里总能挤进 1~3 条相关的。

## 根因

`recall/score.py` 的 `select()` 逻辑是：

```python
top, rest = ranked[:k], ranked[k:]
return top          # 永远返回 k 条，无论分数多低
```

**没有最低分阈值**。即使全部候选的 score 都是 0.1，也会硬凑 8 条。

边界题（应该返回空）也是 2/2 越界，同一个原因：`select` 不会返回空列表。

## 设计期望

DESIGN 第 5 节没有写这条，但参照 PowerContext 的 **Recall Gate**（召回充分性门控）：
召回后评估候选质量，**不足就少给或不给**，而不是硬凑。

候选方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 绝对阈值** | `score < MIN_SCORE`（建议 1.5）的条目丢弃 | 最简单，但分数尺度随权重变化 |
| **B. 相对阈值** | 只保留 `score >= top_score * 0.35` 的 | 自适应，但 top_score 很低时仍会全留 |
| **C. 双阈值** | 绝对 + 相对都满足才留 | 最稳，两个参数要调 |

推荐 **C**：`MIN_ABS = 1.2`、`MIN_REL = 0.35`，并且允许返回空列表。

## 影响

- 每轮注入 81% 是噪声 → token 浪费，且干扰模型注意力
- 边界题（"我朋友是不是喜欢小美"）会拿到无关记忆 → 从"不该知道"变成"可能编"
- 与 ISSUE-0001（无 BM25）叠加：跨表述题靠权重先验蒙，且蒙的时候还带一堆噪声

## 验收标准

1. `ablation.py` 里 `full` 的噪声占比从 81% 降到 **< 50%**
2. 命中率不低于 18/18（不能靠砍噪声把答案也砍掉）
3. 边界题越界从 2/2 降到 **0/2**
4. 新增测试：构造全是低分候选的场景，`select` 返回 `[]` 或明显少于 k 条
5. `python3 benchmarks/run.py` 像人指数不低于 95
