# ISSUE-0017 没有相关性闸门：select 永远凑满 top-k，注入的 81% 是噪声

| 项 | 值 |
|---|---|
| 编号 | ISSUE-0017 |
| 级别 | P1（功能失效：精度系统性偏低） |
| 状态 | merged（PR-0018，证据闸门 + 常驻层） |
| 发现方式 | `benchmarks/ablation.py` 消融实验 |
| 日期 | 2026-10-21 |
| 关联 PR | [PR-0017](PR-0017.md)（merge `8453f93`）、[PR-0018](PR-0018.md)（证据闸门） |

## 症状

消融报告里，**所有配置的噪声占比都在 81%~87%**：

| 配置 | 命中 | 注入字数 | 噪声占比 |
|---|---:|---:|---:|
| `full` | 18/18 | 104 | **81%** |
| `no_dedupe` | 18/18 | 127 | 83% |
| `no_weight_prior` | 16/18 | 126 | **87%** |

也就是说：每注入 5 个字，有 4 个与当前问题无关。命中率漂亮，是因为黄金集只有 20 条，而 top-8 里总能挤进 1~3 条相关的。

## 根因

`recall/score.py` 的 `select()` 逻辑是：

```python
top, rest = ranked[:k], ranked[k:]
return top          # 永远返回 k 条，无论分数多低
```

**没有最低分阈值**。即使全部候选的 score 都是 0.1，也会硬凑 8 条。

边界题（应该返回空）也是 2/2 越界，同一个原因：`select` 不会返回空列表。

## 设计期望

DESIGN 第 5 节没有写这条，但参照 PowerContext 的 **Recall Gate**（召回充分性门控）：
召回后评估候选质量，**不足就少给或不给**，而不是硬凑。

候选方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 绝对阈值** | `score < MIN_SCORE`（建议 1.5）的条目丢弃 | 最简单，但分数尺度随权重变化 |
| **B. 相对阈值** | 只保留 `score >= top_score * 0.35` 的 | 自适应，但 top_score 很低时仍会全留 |
| **C. 双阈值** | 绝对 + 相对都满足才留 | 最稳，两个参数要调 |

推荐 **C**：`MIN_ABS = 1.2`、`MIN_REL = 0.35`，并且允许返回空列表。

## 影响

- 每轮注入 81% 是噪声 → token 浪费，且干扰模型注意力
- 边界题（"我朋友是不是喜欢小美"）会拿到无关记忆 → 从"不该知道"变成"可能编"
- 与 ISSUE-0001（无 BM25）叠加：跨表述题靠权重先验蒙，且蒙的时候还带一堆噪声

## 验收标准

1. `ablation.py` 里 `full` 的噪声占比从 81% 降到 **< 50%**
2. 命中率不低于 18/18（不能靠砍噪声把答案也砍掉）
3. 边界题越界从 2/2 降到 **0/2**
4. 新增测试：构造全是低分候选的场景，`select` 返回 `[]` 或明显少于 k 条
5. `python3 benchmarks/run.py` 像人指数不低于 95

## 进展（PR-0018，2026-10-21）

PR-0017 的双阈值闸门（`score >= max(1.2, top_score × 0.35)`）实测完全无效：
`score()` 里的 weight 先验与 freshness 本身就能把无关记忆顶过 1.2，噪声 81% → 81%。
PR-0018 改为**证据闸门 + 常驻层**：

- **证据闸门**：只有字面（3.0 项）、标签（2.0 项）、情绪对齐（1.5 项）、激活
  （1.5×activation）四项累计的 `evidence` 达到
  `max(MIN_EV_ABS, top_evidence × MIN_EV_REL)` 才注入；`weight` / `freshness` /
  `recent` 只参与排序，不能单独过门。标定值 `MIN_EV_ABS = 0.5`、`MIN_EV_REL = 0.3`
  （三基准同表见 PR-0018）。
- **时钟类问题不检索**：今天几号 / 现在几点 / 今天星期几 等纯问时间消息在
  `select` 入口直接返回 `[]`（带其他实义词的问句有反例测试，不会误杀）。
- **常驻层不经过闸门**：`gate.pinned(cache)` 取 active 的全部 persona + 印象层
  按 weight 前 2，在 `main._recall_block`、`benchmarks/ablation.py`、`run.py` /
  `scale.py` 注入前并入（DESIGN 5.3 头部常驻的落地）。人格底色类问句证据天然为
  零，不能由相关性闸门决定去留；代价是每轮固定约 38 字画像开销。
- **消融口径修订**：边界题不再要求注入块为空，改看「正文泄露」（红线 0）与
  「边界注入字数」；字数拆「常驻层（固定开销）」与「检索层字数/检索层噪声」，
  噪声只统计检索层。影子遮蔽句是 DESIGN 7.4 的既定行为，不算越界。
- **基准数据保真修复**：合成记忆补 tags（与生产 `perceive/extract` 输出同构）、
  修正一处层级标注（事件 fact ↔ 期望 detail → `fact`）；未改任何 expect 文本。

### 结论

- ablation 三条核心红线（检索层噪声 / 命中 / 正文泄露）、时钟题与常驻层测试
  全部达标；证据闸门 + 常驻层的机制成立。
- `run.py` 的最后一分缺口是「我是不是跟你说过一件事不让说」：旧期望要求召回
  别人的秘密正文 `私事`，与 DESIGN 秘密/影子语义冲突（只交付遮蔽句、不交付正文），
  该题在 PR-0003 基线里同样是 0/1。修正期望值为「不应召回」后 `run.py` = **100**；
  修正理由与分母变化写在 PR-0018。**该基准至此饱和**，见 ISSUE-0019。
- `scale.py` 5/6 与 ablation 掉的「我是干什么的」同源（零证据检索）；
  `docs/BASELINES.md` 里伪向量方案在同一数据上也是 5/6。
