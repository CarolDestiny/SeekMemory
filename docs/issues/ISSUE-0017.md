# ISSUE-0017 没有相关性闸门：select 永远凑满 top-k，注入的 81% 是噪声

| 项 | 值 |
|---|---|
| 编号 | ISSUE-0017 |
| 级别 | P1（功能失效：精度系统性偏低） |
| 状态 | open（PR-0017 的双阈值闸门无效；PR-0018 证据闸门待合并） |
| 发现方式 | `benchmarks/ablation.py` 消融实验 |
| 日期 | 2026-10-21 |
| 关联 PR | [PR-0017](PR-0017.md)（merge `8453f93`）、[PR-0018](PR-0018.md)（证据闸门） |

## 症状

消融报告里，**所有配置的噪声占比都在 81%~87%**：

| 配置 | 命中 | 注入字数 | 噪声占比 |
|---|---:|---:|---:|
| `full` | 18/18 | 104 | **81%** |
| `no_dedupe` | 18/18 | 127 | 83% |
| `no_weight_prior` | 16/18 | 126 | **87%** |

也就是说：每注入 5 个字，有 4 个与当前问题无关。命中率漂亮，是因为黄金集只有 20 条，而 top-8 里总能挤进 1~3 条相关的。

## 根因

`recall/score.py` 的 `select()` 逻辑是：

```python
top, rest = ranked[:k], ranked[k:]
return top          # 永远返回 k 条，无论分数多低
```

**没有最低分阈值**。即使全部候选的 score 都是 0.1，也会硬凑 8 条。

边界题（应该返回空）也是 2/2 越界，同一个原因：`select` 不会返回空列表。

## 设计期望

DESIGN 第 5 节没有写这条，但参照 PowerContext 的 **Recall Gate**（召回充分性门控）：
召回后评估候选质量，**不足就少给或不给**，而不是硬凑。

候选方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 绝对阈值** | `score < MIN_SCORE`（建议 1.5）的条目丢弃 | 最简单，但分数尺度随权重变化 |
| **B. 相对阈值** | 只保留 `score >= top_score * 0.35` 的 | 自适应，但 top_score 很低时仍会全留 |
| **C. 双阈值** | 绝对 + 相对都满足才留 | 最稳，两个参数要调 |

推荐 **C**：`MIN_ABS = 1.2`、`MIN_REL = 0.35`，并且允许返回空列表。

## 影响

- 每轮注入 81% 是噪声 → token 浪费，且干扰模型注意力
- 边界题（"我朋友是不是喜欢小美"）会拿到无关记忆 → 从"不该知道"变成"可能编"
- 与 ISSUE-0001（无 BM25）叠加：跨表述题靠权重先验蒙，且蒙的时候还带一堆噪声

## 验收标准

1. `ablation.py` 里 `full` 的噪声占比从 81% 降到 **< 50%**
2. 命中率不低于 18/18（不能靠砍噪声把答案也砍掉）
3. 边界题越界从 2/2 降到 **0/2**
4. 新增测试：构造全是低分候选的场景，`select` 返回 `[]` 或明显少于 k 条
5. `python3 benchmarks/run.py` 像人指数不低于 95

## 进展（PR-0017，2026-10-21）

代码已合入 `main`（`8453f93`），但**验收未全部达标，issue 保持 open**：

| 验收项 | 目标 | 实测 | 结论 |
|---|---|---|---|
| `full` 噪声占比 | < 50% | 81% | 未达标 |
| 命中率 | ≥ 18/18 | 18/18 | 达标 |
| 边界题越界 | 0/2 | 2/2 | 未达标 |
| `run.py` 像人指数 | ≥ 95 | 98 | 达标 |
| `scale.py` 召回 | 6/6 | 6/6 | 达标 |

已实现：`select(gate=True, min_abs=1.2, min_rel=0.35)` 双阈值、允许返回空、
`gate=False` 向后兼容、两个配置项、7 条新测试。未达标原因见 PR-0017：
综合分里的权重先验/激活本身就能把噪声抬过 1.2，而边界题的 top-1 是字面
高度重合的短期琐事/shadow 秘密，阈值无法区分“字面像”和“该不该召回”。

后续需要单独开 issue：query 意图判断（时间类问题不查长期记忆）、shadow
交付策略，以及「零字面题靠权重先验」与「噪声截断」之间的排序改造。

## 进展（PR-0018，2026-10-21）

PR-0017 的双阈值闸门（`score >= max(1.2, top_score × 0.35)`）实测完全无效：
`score()` 里的 weight 先验与 freshness 本身就能把无关记忆顶过 1.2，噪声 81% → 81%。
PR-0018 改为**证据闸门**：

- 只有字面（3.0 项）、标签（2.0 项）、情绪对齐（1.5 项）、激活（1.5×activation）
  四项累计的 `evidence` 达到 `max(MIN_EV_ABS, top_evidence × MIN_EV_REL)` 才注入；
  `weight` / `freshness` / `recent` 只参与排序，不能单独过门。
  标定值 `MIN_EV_ABS = 0.5`、`MIN_EV_REL = 0.3`（三基准同表见 PR-0018）。
- 纯问时间的时钟类消息（今天几号 / 现在几点 / 今天星期几 等）不检索长期记忆。
- 消融边界题口径修订：不再要求注入块为空，改看「正文泄露」与「边界注入字数」；
  「你记得，有件事你答应过别人不说」是 DESIGN 7.4 要求的影子遮蔽句，不算越界。
- 数据保真修复：benchmark 合成记忆补上 tags（与生产 `perceive/extract` 输出同构），
  未改黄金集、未改任何期望值。

### 修订后的验收对照（Lead 2026-10-21 拍板的口径）

| # | 验收项 | 修订后目标 | 实测 | 结论 |
|---|---|---|---|---|
| 1 | `ablation` `full` 噪声 | < 45% | **37%** | ✅ |
| 2 | `ablation` 命中 | ≥ 16/18 且列出掉题 | **16/18**，掉「我是干什么的」「你最了解我什么」 | ✅（归 ISSUE-0001） |
| 3 | 边界题 | 正文泄露 0；时钟题 0 注入 | **泄露 0**；「今天几号」0 字 | ✅ |
| 4 | 新增测试 | ≥ 10 条 | `tests/test_gate.py` 7 → **17 条**（净增 10） | ✅ |
| 5 | `run.py` 像人指数 | ≥ 95 | **84**（层级 57% / 召回 71%） | ❌ 见下 |
| 6 | `scale.py` 召回 | 6/6 | **5/6** | ❌ 见下 |

第 2 项掉的 2 题与第 5/6 项未达是**同一个原因**：`我是干什么的`、`你最了解我什么`、
`你觉得我这个人怎么样` 这类问句与记忆零字面、零标签、零激活，只能靠 weight 先验
或语义检索命中；证据闸门按设计不再为它们放行通用高权重记忆（放开就回到 81% 噪声）。
`run.py` 另外还有一处层级标注不一致（「你还记得我名字吗」期望 detail、命中 fact 层，
未改期望值）与一道秘密交付题。逐题 evidence/floor 诊断见 PR-0018；要同时满足
「噪声 < 45%」与「零证据题也命中」需要等 ISSUE-0001（BM25/向量）。

### 结论

- ablation 三条核心红线（噪声 / 命中 / 泄露）与时钟题已达标；证据闸门机制成立。
- `run.py` 84、`scale.py` 5/6 是「精度换召回」的已知代价，已逐题记录。
  是否接受该代价、ISSUE-0017 是否关闭，由 Lead 在合并 PR-0018 时裁决。
