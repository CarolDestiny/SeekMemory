## 改动摘要

- **读路径按 scope 过滤（ISSUE-0003）**：新增 `recall/scope.py`，`main._visible()` 在
  `seed → select → assemble` 之前按当前会话 `unified_msg_origin` 过滤候选池。
  `private` 只给归属会话；归属按 `payload["owner_umo"]`（写入时记录）→
  `lineage.sources` 反查 `sources.umo`（新增 `DB.source_umo()`）→ `said_by` 里的 umo
  依次推导；三者都没有的老数据按“只给配置的 `owner_umo` 会话”处理。`shared` 与
  `shadow` 所有会话都保留。
- **shadow 正文遮蔽（ISSUE-0003）**：`assemble._sentence()` 先判 `header.scope`，
  `scope=shadow` 一律只输出影子句（`shadow_text`，缺失时用固定句“有件事你答应过
  别人不说”），不再走 `_memory_sentence()`；`_dedupe()` 也改用影子句做键，避免
  正文参与比较。`family=secret` 的原保护保持不变。
- **designated 归还（ISSUE-0004）**：新增 `recall/designated.py`，实现三条硬条件：
  ① `event.is_private_chat()`；② 消息命中 `payload["trigger"]`（字符串按空格/逗号/
  顿号拆分，也支持列表；去空白后精确子串）；③ `given` 为空。命中后 `assemble`
  输出完整 `payload["text"]`，`mark_given()` 写回 `given` 时间戳并更新 cache；
  群里问、私聊未触发、已给过都不注入正文。已在 `given` 的条目再次触发不会重复交付。
- **写入侧补归属**：`main._pending` 从 `(role, text)` 改成 `(umo, role, text)`；
  单会话批次夜间写入时给 payload 补 `owner_umo`，让新数据的 private 隔离真正生效。
- **明确没改**：`core/artifact.py` 的 `Header` 结构未动；`perceive/extract.py` 未改；
  RBAC / 预算未改；`benchmarks/*` 未改（脚本仍自行预过滤，生产路径的隔离由本次
  实现与本 PR 的测试独立保证）。
- 文档同步：`docs/CONTRACT.md`（`build` 可选上下文、新模块、`DB.source_umo`）、
  `docs/INDEX.md`（读路径）、`recall/README.md`、`store/README.md`。

## 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 老数据没有归属信息，且未配置 `owner_umo` | 这些 `private` 记忆对所有会话都不可见 | 按 issue 要求保守处理；升级后建议先配 `owner_umo`。新写入会自动带 `owner_umo` |
| 一个夜间批次跨多个会话（如 owner 当天既私聊又群聊） | 批次 umo 不唯一时不给 `owner_umo`，private 退回 owner 兜底，部分群记忆可能不可见 | 宁可少注入不跨会话泄漏；按会话拆分抽取留待 ISSUE-0013/SOURCE 链路 |
| `event.is_private_chat()` 在不同 AstrBot 版本上缺失 | 取不到时按群聊处理，designated 不交付 | fail-open 到“不交付”，不会误把正文发到群里 |
| shadow 正文仍参与 seed/select 打分（只是不输出） | 理论上存在“是否被选中”的侧信道，但不泄露文本 | 与 DESIGN §7.4「影子全局可见、内容不可见」一致；如需彻底隔离再改索引层 |
| 旧调用 `build(arts)` 未传会话上下文 | designated 仍只给托付提示，不会交付正文 | 仅脚本/旧测试受影响；生产 `main` 已传 `text` 与 `is_private` |
| 预算裁剪把 designated 正文截断 | 超长正文可能不完整 | designated 在 `main` 中排在候选最前，优先进入头部；`mark_given` 只对正文确实出现在 block 里的条目写回 |

回滚：`git revert -m 1 <merge-commit>`。
