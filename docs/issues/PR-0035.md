## 改动摘要

- **仅评测/基准，无生产行为变更**：不改 `services/`、`perceive/`、`recall/`、`store/` 的运行时逻辑，
  不改数据库 schema、公开配置或 API。
- 新增冻结的 40 主题合成语料（fact 24 / behavior 8 / chatter 5 / backlog 3），
  覆盖用户事实、bot 行为、低价值闲聊和积压。
- 新增确定性 harness：在隔离的内存 SQLite 上走生产
  `DreamCycle -> IngestService.flush` 路径，用按 Source id 索引的 recorded provider 返回
  fake 抽取结果；不访问网络，不提交真实聊天正文。
- 新增多 checkout 对比/报告生成器，记录 `cc814ce` 与 `d9fc248` 的前后差异、pending 增长模拟、
  显式阈值和建议。
- 新增结果快照与生成结果政策：说明 canonical 文件、`current` 如何重新生成、
  `cc814ce`/`d9fc248` 为不可变历史，以及 `environment.platform=win32` 只是历史来源。
- 新增回归测试 `tests/test_dream_eval.py`：确定性、内容零泄漏、`IngestService` 仍是唯一
  Artifact 写入路径。

**明确不改**：分诊算法、同会话批大小、Dream 调用/token 预算、recall 路径、数据库 schema、
生产服务/DI/registry。本 PR 只负责测量 PR #79 的 tradeoff，并给出后续调参建议。

## 为什么结果是 NOT_ACCEPTED

| 指标 | cc814ce | d9fc248 | 阈值 |
|---|---:|---:|---:|
| 抽取调用 | 40 | 8（-80.0%） | 调用下降 ≥50% |
| 总 token | 68,199 | 18,523（-72.8%） | token 下降 ≥50% |
| 重要事实召回 | 23/23 | 15/23（65.2%） | ≥85% |
| bot 行为覆盖 | 8/8 | 7/8（87.5%） | ≥85% |
| 自我印象覆盖 | 1/1 | 0/1（0%） | ≥85% |
| 错误记忆率 | 20.5% | 0.0% | ≤10% |
| 重复率 | 0.0% | 0.0% | ≤2% |
| pending 主题 | 0 | 17（9 重要 + 8 低价值） | 比例 ≤50% |

成本、去噪、重复率通过；重要事实召回、自我印象覆盖未达标，且 pending 在 Dream-only
分诊下每晚线性增长 8 个主题、没有上界。因此报告判定为 `NOT_ACCEPTED`，而不是“优化成功”。

## 兼容性、数据与隐私

- **无生产兼容性影响**：没有 schema migration、配置字段、API 变更或持久化数据格式变更。
- **无第二写入路径**：没有新增服务、表、DI、registry；`IngestService` 仍是唯一抽取 Artifact
  写入者，回归测试用 commit spy 断言调用方只有 `ingest_service.py`。
- **无真实聊天正文**：语料全部 `synthetic: true`；报告只含计数、标签和 topic id；
  120 条语料文本在 5 个结果文件中 0 泄漏。
- **token 口径**：`usage_in/out` 是按字符估算，`usage_cached=0`（未模拟前缀缓存）；
  横向对比有效，但不是 provider 上报值。
- **平台元数据**：`environment.platform=win32` 是生成已提交快照的机器来源，不是跨平台断言；
  harness 使用内存 SQLite、固定时钟和确定性 provider，CI 在 Linux 上应复现相同计数。
- **生成结果政策**：`benchmarks/results/README.md` 明确 canonical 文件、`current` 重生成方式、
  `cc814ce`/`d9fc248` 的不可变历史和平台元数据说明。
