## 改动摘要

人格与印象的进化从"随时发生"收敛成每天一次的 dream 周期。

- **`app/dream.py`**：新增 `DreamCycle` / `DreamResult`。
  - `due()`：到 `dream_time`（默认 03:30）且当天未完成才为真；
  - `run()`：按批次循环调用注入的 `flush_once`，直到没有待抽取行或达到
    `dream_max_batches`（默认 12）；随后执行 `maintain`（遗忘 / 合并 / 人格沉淀）；
  - 台账主键是日期，**当天已 done 直接跳过**（幂等）；中途失败写 `failed`，
    待抽取行留在 `extraction_state`，下一次从断点续跑。
- **`store/schema.sql` + `store/db.py`**：新增 `dream_runs` 表与
  `dream_get` / `dream_begin` / `dream_finish` / `dream_recent`。
  SQL 仍只在 `store/db.py`。
- **`app/flush_policy.py`**：`decide_flush` 增加 `dream_only` 参数并**放在最前面**，
  连 topic 过期也不能越过；这是修 0.3.1 里 backlog 分支绕过白天开关的问题。
- **`main.py`**：
  - 梦境开启时不再启动 `_idle_loop` / `_nightly_loop`，改为 `_dream_loop`；
    启动时若已过点且当天没做完，立即补跑一次；
  - `_flush` 返回 `(written, batches)`，供梦境计数；
  - `_weekly` 返回统计，作为梦境摘要；
  - `_should_flush` 在梦境模式下恒为 False（容量保护动作也不触发抽取）。
- **面板**：`webui/routes.py` 的状态接口新增 `dream` 与 `budget` 两块。

## 验证方式

```bash
python3 -m unittest discover -s tests -p "test_*.py" -q
```

结果：`Ran 279 tests`，与 main 基线一致的 4 个环境相关 import error（缺 AstrBot 运行时），
其余全过；新增 `tests/test_dream.py` 12 条，覆盖：

1. 到点前不触发；2. 到点后触发；3. 关闭时永不触发；
4. 当天只跑一次（幂等）；5. 失败保留待抽取、当天可续跑；
6. `dream_max_batches` 上限生效；7. maintain 在抽取后执行；
8. `decide_flush(dream_only=True)` 恒返回 False。

线上验证（部署 v0.4.0 后）：白天不再出现 `空闲 extract` 日志；dream 时刻出现
一条 `梦境 <date> done：N 个话题，写入 M 条`；`dream_runs` 表每天一行。

## 风险与回滚

- 风险：dream 时间设置过晚会导致当天记忆延迟生效；`dream_enabled=false`
  可回到旧的夜间/空闲抽取行为。
- 回滚：`git revert` 本提交并重新部署上一 tag（v0.3.1 备份仍在服务器
  `~/qqbot/plugin_backup/`）。
