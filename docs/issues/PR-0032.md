# PR-0032：为 Agent 运行增加无正文的轨迹与管理时间轴

关联 [GitHub #11](https://github.com/NeverENG/SeekMemory/issues/11) / [ISSUE-0032](ISSUE-0032.md)。本地实现，尚未提交远端 PR。

一次回复现在可以关联模型请求、召回决策、工具调用与发送事件。管理员在“运行轨迹”按召回结果筛选，展开披露详情，并点击 Artifact ID 进入已有审计抽屉。
例如，记忆进入上下文但模型失败时，页面显示“记忆已注入”和“未记录发送成功”，不会误称记忆已说出。

## 实现

- `app/runtime/tracing.py`：把同一宿主消息上的回调归到一个随机 run_id，支持请求先于 begin、重复请求和重复发送回调。
- `app/runtime/trace_data.py`：白名单过滤元数据；聚合运行与互不排斥的筛选标签。
- `store/run_trace.py`：JSONL 持久化、重载、保留期限与条数清理。普通写入追加，清理原子替换，容量满时最多提前淘汰 1% 以摊薄重写成本。
- `main.py`：仅映射宿主已有回调；未执行或失败的召回不伪装为正常零命中。
- `recall/score.py` / `pipeline.py`：从既有选取过程采集计数，不复制或改动 gate 算法。
- `GET manage/traces`：使用现有管理员认证，可选 state 筛选；OpenAPI、生成类型、Zod 与真实后端响应样本同步。
- Dashboard：列表、时间轴、披露/相关性详情、工具耗时、过滤和 Artifact 抽屉；独立 Hook 处理异步读取和过期响应。

## 限制与风险

- **真实 AstrBot 宿主未安装，合入前仍需 staging 验证和维护者审核。** 重点验证 begin/request 的实际顺序、工具循环、失败路径和 after_message_sent 的语义。
- 文件为单插件实例写入；不提供跨进程共享写日志保证。同步本地磁盘 I/O 有开销；追加和批量清理减少重写频率。
- 每个 ID 列表和披露映射最多 256 项；超出截断。保留上限是事件数，可能只剩半次运行，页面明确提示。
- 写入失败的事件可能缺失，不重试模型或业务操作；恢复时继续记轨迹。时间轴不等于可靠业务账本，Source/Artifact/SQLite Episode 仍承担原有职责。
- 工具结果缺少可靠的宿主成功标识，状态保持 unknown；重叠调用无法配对时耗时为空。
- 默认不自动轮询；点击“刷新轨迹”读取最新数据。事件日志不保存正文，现有详情抽屉仍按管理员权限读取 Artifact。
