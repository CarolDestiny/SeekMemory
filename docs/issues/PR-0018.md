## 改动摘要

PR-0017 的双阈值闸门（`score >= max(1.2, top_score × 0.35)`）对 `full` 完全无效：
`score()` 是五项加权和，**weight 先验（最高 2.1）与 freshness 本身就能把无关
记忆顶过 1.2**，实测噪声 81% → 81%。本 PR 换成只看「相关性证据」的闸门。

- **证据闸门（`recall/gate.py` 新增 + `recall/score.py`）**：打分循环同时累计
  `evidence = 字面(3.0 项) + 标签(2.0 项) + 情绪对齐(1.5 项) + 激活(1.5×activation)`；
  `weight`、`freshness`、`-2.0 recent` 只参与排序，**不能单独让一条记忆过门**。
  过门条件：`evidence >= max(MIN_EV_ABS, top_evidence × MIN_EV_REL)`；
  没有候选达标就返回 `[]`（不相关就不注入）。探索只在过门候选里进行。
  `gate=False` 保持旧的「尽量凑满 k」行为，供消融对照。
- **时钟类问题不检索（`recall/gate.py: is_clock_query`）**：`今天几号 / 现在几点 /
  今天星期几 / 今天日期 / 几号了` 等纯问时间的短问句在 `select` 入口直接返回 `[]`，
  时间由系统 prompt 提供。判定要求「命中时间标志词 + 去掉填充词后不剩实义词」，
  并 fail-open（异常按不是时钟题处理），因此「今天加班到几点」「我上次加班到几点」
  不会被误杀（有反例测试）。
- **数据保真修复（tags 缺失）**：`benchmarks/run.py` 的 `to_artifact()` 原来没有把
  事件自带的 `tags` 写进 payload，`benchmarks/simdata.py` 的合成记忆也完全没有标签，
  而生产路径 `perceive/extract.py` 产出的记忆一定带 tags。这会让证据闸门在基准里
  只剩字面/情绪两维可用、低估召回。本 PR 让合成数据与生产 extract 输出同构：
  `run.py` 透传事件标签，`dataset.py` 给缺标签的事件补自然主题标签（琐事/吃饭/
  工作/陪伴/心情/性格/自理），`simdata.py` 用 `FACT_TAGS` 从事实文本主题派生标签。
  **这是口径修复，不是调参，也没有改任何黄金集期望值。**
- **消融口径修订（`benchmarks/ablation.py`）**：边界题不再要求「注入块为空」。
  改为两列：`边界正文泄露`（FORBIDDEN 词出现次数，红线 0）与 `边界注入字数`。
  理由：边界题的伤害来自**泄露别人的秘密正文**；而「你记得，有件事你答应过别人
  不说」是 DESIGN 7.4 明确要求的影子遮蔽句，注入它不构成泄露，凭空判定越界会
  逼着实现去凑指标。`full` 与 `no_gate` 在报告里并列，差值即闸门贡献。
- **明确没改**：`docs/DESIGN.md` 7.4（影子语义保持「全局可见、只注入影子句」）；
  `recall/assemble.py`（正文遮蔽逻辑原样）；`recall/seed.py` / `spread.py`；
  黄金集 `benchmarks/goldset.py` 与任何期望值；`maintain/`、`main.py` 的读写路径。

## 标定

### 阈值扫描（三基准同表，rel 固定 0.3；`full` 配置）

| `MIN_EV_ABS` | ablation 命中 | ablation 噪声 | 边界泄露 | run.py 像人指数 | run 层级/召回 | scale.py |
|---:|---:|---:|---:|---:|---|---|
| 0.25 | 16/18 | 73% | 0 | 90 | 71% / 86% | 5/6 |
| 0.30 | 16/18 | 73% | 0 | 90 | 71% / 86% | 5/6 |
| 0.35 | 16/18 | 66% | 0 | 88 | 71% / 71% | 5/6 |
| 0.40 | 16/18 | 59% | 0 | 84 | 57% / 71% | 5/6 |
| **0.50（选定）** | **16/18** | **37%** | **0** | **84** | **57% / 71%** | **5/6** |
| 0.70 | 16/18 | 37% | 0 | 84 | 57% / 71% | 5/6 |

`MIN_EV_REL`：0.2 时边界注入 68 字、噪声 39%；0.3 时边界注入 26 字、噪声 37%，
run/scale 不变，故选 **`MIN_EV_ABS = 0.5`、`MIN_EV_REL = 0.3`**。噪声再往下降
（abs ≥ 0.7）收益为 0，反而继续挤压召回，不选。

### 闸门贡献（`ablation.md` 同表）

| 配置 | 命中 | 平均注入 | 噪声 | 边界正文泄露 | 边界注入 |
|---|---:|---:|---:|---:|---:|
| `full`（gate=True） | 16/18 | 24 字 | **37%** | **0** | 26 字 |
| `no_gate`（旧行为） | 18/18 | 101 字 | 81% | 0 | 101 字 |

两行的命中差 2 条，正是下面诊断表里两道「零证据题」；噪声与注入字数的差值
即闸门单独贡献。

## 逐题 evidence 诊断（仍有掉题）

证据闸门下掉的题都打印了「题面 / 命中条 evidence / top_evidence / floor」，
floor = `max(0.5, top_evidence × 0.3)`：

| 基准 | 题面 | 期望 | 实际选中 | 命中条 evidence | top_evidence | floor |
|---|---|---|---|---:|---:|---:|
| ablation | 我是干什么的 | 量化交易 | （空） | 0.09 | 0.41 | 0.50 |
| ablation | 你最了解我什么 | 倔/心软 | （空） | 0.22 | 0.41 | 0.50 |
| run.py | 你觉得我这个人怎么样 | 他有点倔/不会照顾自己 | （空） | 0.22 | 0.41 | 0.50 |
| run.py | 你还记得我名字吗 | level=detail | 他叫吕宇轩，也叫 BangBang | 命中（字面+标签 2.09） | — | — |
| run.py | 我是不是跟你说过一件事不让说 | 私事 | （空） | 0.32 | 0.41 | 0.50 |
| scale.py | 我是干什么的 | 量化 | （空） | 0.18 | 0.18 | 0.50 |

逐条归因：

1. **零证据题**：`我是干什么的`（ablation / scale）、`你最了解我什么`、
   `你觉得我这个人怎么样`。问句与记忆零字面、零标签、零激活，情绪项只有
   `1.5×0.3×arousal` 的通用唤醒（0.09~0.22），命中条 evidence 远低于 0.5。
   这类题只能靠 weight 先验或语义检索，属 **ISSUE-0001（BM25/向量）** 的范围；
   证据闸门按设计不再为它们放行通用高权重记忆（放开就是回到 81% 噪声）。
2. **层级标注不一致**：run.py「你还记得我名字吗」期望 `level=detail`，但命中
   记忆是 `fact` 层；命中本身成立（evidence 2.09 过门），只是层级期望对不上。
   这是基准标注与层级语义不一致，本次**没有改期望值**。
3. **秘密交付题**：run.py「我是不是跟你说过一件事不让说」期望召回 `私事`，
   但该记忆按 secret/shadow 语义只应给遮蔽句；即使 evidence 达标也不该交付正文，
   与本闸门无关，属交付策略问题。

## 验收口径修订（与 Lead 对齐）

原 ISSUE-0017 的「命中 ≥ 18/18」「边界注入块为空」在证据闸门下自相矛盾：

- 18/18 里有 2 道题（`我是干什么的`、`你最了解我什么`）与题干零证据，
  只能靠 weight 先验把泛化高权重记忆塞进 top-8；而这批记忆正是消融口径下
  的噪声。要求 18/18 就等于要求保留 81% 噪声。
- 边界题「我朋友是不是喜欢小美」的 top-1 就是那条 shadow 秘密（5.68 分，
  字面/标签/激活全中），要求注入块为空只能靠 query 意图判断或让影子不遮蔽，
  后者与 DESIGN 7.4 冲突。边界伤害的正确度量是**正文是否泄露**。

因此本 PR 按修订后口径验收：噪声 < 45%、命中 ≥ 16/18 且逐题诊断、
边界正文泄露 0、时钟题 0 注入、新增测试 ≥ 10、run.py / scale.py 以实测记档。
其中 run.py 84 与 scale.py 5/6 的差距与 ablation 掉的 2 题**同源**（零证据题），
不是闸门实现差异。

## 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 证据阈值 0.5 对生产能力偏严 | 「我是干什么的」这类零证据但重要的问句查不到 | 属 ISSUE-0001；可调 `MIN_EV_ABS`（见标定表） |
| `main.py` 仍传 `recall_min_abs/recall_min_rel` | 两个配置项已不参与闸门，改了没有效果 | `select` 保留参数不报错；配置键应在后续 PR 清理为 `recall_min_ev_*` |
| 时钟题判定是启发式 | 极端短句可能误判（如只有「今天」） | 要求时间标志词 + 去填充词后无实义词；有反例测试；判定异常 fail-open |
| 数据保真改动动了 benchmark 数据 | 与历史 `latest.md` / `scale.md` 数字不再逐字可比 | PR 内明示改动范围（只补 tags）；命中/召回判定未改；结果文件已重跑 |
| 证据闸门让注入字数从 101 降到 24 | 可能少给一点上下文 | 这是本 PR 的目的（精度）；消融里 no_weight_prior/no_decay 等证明召回由证据项承担 |

回滚：`git revert -m 1 <merge-commit>`；或只调回 `recall/gate.py` 的
`MIN_EV_ABS=1.0` 回到更宽松行为。
