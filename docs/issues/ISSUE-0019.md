# ISSUE-0019 静态黄金集饱和：run.py 顶到 100，区分度没了

| 项 | 值 |
|---|---|
| 编号 | ISSUE-0019 |
| 级别 | P2（评测失效：基准测不出改进） |
| 状态 | open |
| 发现方式 | PR-0018 收尾时三基准同时到顶 |
| 日期 | 2026-10-21 |
| 关联 PR | 待开（建议分支 `bench/harder-goldset`） |

## 症状

PR-0018（证据闸门 + 常驻层）之后：

| 基准 | 结果 | 天花板 | 还能区分好坏吗 |
|---|---:|---:|---|
| `benchmarks/run.py` 像人指数 | **100 / 100** | 100 | 不能 |
| `benchmarks/ablation.py` `full` 命中 | **17/18** | 18 | 只剩 1 题余量，且那题已知要等 ISSUE-0001 |
| `benchmarks/scale.py` 召回 | **5/6** | 6 | 只剩零证据题 |

三个静态基准全部贴住天花板。本轮它们确实抓到了问题（噪声 81% → 40%、秘密交付
期望写错），但**再用它们验证下一轮改动会得到"没有变化"的假结论**。

## 根因

1. **题目都是单跳的**：每题一条记忆就能答，考的是"找不找到"，不是"串不串得起来"。
2. **没有时序与冲突**：没有"先说要辞职、后来说算了"这类需要版本时序与撤回的题，
   而这正是 DESIGN 里版本时序 + 遗忘曲线的核心卖点。
3. **没有跨会话边界题**：群聊里问私聊的事、A 问 B 的事，只有 2 道边界题。
4. **数据规模太小**：`ablation` 池子只有几百条，`large_e2e` 的 31,926 条才是真实量级。

## 影响

- 像人指数、召回率这类 headline 数字不再随实现变化，等于失去回归保护。
- 容易误判"这个改动没用"，或反过来把噪声当收益。

## 设计期望

新增一组**难任务集**，与现有基准并列（不替换，现有三基准继续当冒烟）：

| 类别 | 例子 | 考什么 |
|---|---|---|
| 多跳 | "我面试过的那家公司，后来给我开了多少" | 两条记忆串起来 |
| 时序/撤回 | "我最后还打算辞职吗"（先说辞职，后来说算了） | 版本时序 + pending 失效 |
| 冲突消解 | "我到底是要去北京还是上海"（两段自相矛盾的话） | 版本新旧与置信 |
| 长尾指代 | "那个蓝色的、会咬键盘的东西叫什么" | 描述性指代 → 唯一实体 |
| 跨会话 | 群聊里问只在私聊说过的事 | scope 边界 |
| 反事实 | "如果我当时没换工作会怎样" | 不该召回的假设题 |

数据来源：优先从 `large_e2e` 的漏题（3 题）与 `large_e2e` 60 题里命中率低的类别
（decay 6/7、impression 5/6、boundary 3/7）反推，而不是凭空编。

## 验收标准

1. 新任务集 ≥ 30 题，每类 ≥ 4 题，期望值可字符串判定（或给出判定脚本）。
2. 在当前实现上跑出的分数**落在 40%~80% 区间**（有区分度，不封顶也不地板）。
3. 至少 3 道题能证明"关掉某个组件就答不出"（与 `ablation` 同思路）。
4. 接入 `benchmarks/run.py` 或独立 `benchmarks/hard.py`，输出可复现（固定种子/固定数据）。
5. 不修改现有三基准的题目与期望（饱和就如实标注，不改题凑分）。

## 关联

- PR-0018 报告了本 issue 的前身现象（run.py 100/100）。
- `benchmarks/results/large_e2e.md` 的漏题清单是第一手素材。
- 与 ISSUE-0001（语义检索）互补：0001 让"找不到"变"找得到"，本 issue 让"测得出找得好不好"。
